# BeatIt

화면 맨 위에 떠 있는 샌드백 위젯. 클릭하면 줘터지고, 연타하면 콤보가 쌓인다.

## 받아서 바로 쓰기

[**Releases**](https://github.com/parkrye/WidgetProject_BeatIt/releases/latest) 에 exe 두 개가 붙어 있다. 하나만 받으면 된다.

| 파일 | 크기 | 조건 |
|---|---|---|
| `BeatIt-standalone.exe` | 약 63MB | **아무것도 설치 안 해도 바로 실행된다.** 남한테 줄 거면 이걸 준다 |
| `BeatIt.exe` | 약 2MB | 가볍지만 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) 이 깔려 있어야 한다 |

기본 캐릭터와 테마는 exe 안에 들어 있고 첫 실행 때 `%AppData%\BeatIt\` 로 풀린다. 따라다닐 파일이 없다.

> exe 는 저장소에 담지 않는다. 63MB 짜리가 커밋마다 히스토리에 쌓이면 소스 1MB 짜리를 받는 데 그만큼이 딸려온다.

## 직접 빌드

```bash
dotnet run --project src/BeatIt     # 개발 중 실행
```

```powershell
.\publish.ps1                       # 루트에 exe 두 개를 만든다 (gitignore 에 걸려 있다)
```

## 조작

| 입력 | 동작 |
|---|---|
| 좌클릭 | 타격. 꾸겨졌다 튀어오르고 `beat` 이미지로 바뀌며 이펙트가 튄다. **때린 자리에 따라 그림이 갈린다** |
| 좌클릭 연타 | 콤보 누적. 숫자가 커지고 색이 붉어지며 타격 강도도 세진다 |
| 좌클릭 드래그 | 붙잡은 지점이 커서를 따라오고 몸통은 뒤처지며 쭉 늘어난다. **가는 쪽의** `move` 이미지로 바뀌고, 놓으면 출렁이며 돌아온다 |
| 드래그 후 뿌리기 | **집어던지기**를 켜두면 놓은 속도로 날아가 이동 영역 벽에 통 하고 튕긴다. 날아가는 중에 누르면 공중에서 낚아챈다 |
| 우클릭 | 설정 / 돌아다니기 / 항상 위에 / 위치 잠금 / 종료 |
| 커서 올리기 | 돌아다니던 중이면 **멈춰 선다.** 커서가 비키면 다시 걷는다 |

가만히 두면 `idle` 이미지 중 하나가 설정한 간격 안에서 랜덤하게 갈아 끼워진다.
**돌아다니기**를 켜면 **이동 영역** 안에서 목적지를 골라 걸어가고 도착하면 잠깐 쉰다.
때리거나 끌면 멈추고, **커서를 올려두면 그동안 멈춰 선다.** 걸어서 커서 밑을 빠져나가면 조준한 클릭이 허공을 때리기 때문이다.
설정 창이나 이동 영역 오버레이가 떠 있는 동안에도 걷지 않는다.
캐릭터에 소리를 넣어두었으면 때릴 때·움직일 때·가만히 있을 때 각각 울린다.

콤보 숫자는 **캐릭터 머리 위에 밑변을 붙이고 위로 자란다.** 아무리 커져도 캐릭터를 안 덮는다.
**50 콤보마다 한 계단씩** 커지고 색이 바뀌며, 그 자리에서 숫자가 번쩍이고 캐릭터 둘레로 이펙트가 터진다.
1000 콤보에서 색 스펙트럼을 다 쓰고 나면 은은한 무지개가 돌기 시작한다. 크기는 그 뒤로도 천천히 자라다 최대 배율에서 선다.

## 설정

우클릭 → **설정**. 탭 다섯 개로 나뉘어 있고, **값을 만지는 즉시 위젯에 반영된다.** 취소를 누르면 열기 전으로 되돌아간다.
**설명은 커서를 올렸을 때만 뜬다.** 길든 짧든 창에 박아두면 정작 값이 안 보인다.

| 탭 | 들어 있는 것 | 상세 설정 |
|---|---|---|
| 캐릭터 | 캐릭터 고르기 / 캐릭터 관리 / 폴더 열기 | |
| 테마 | 테마 고르기 / 테마 관리, 타격 이펙트 on/off, 콤보 숫자 크기와 가로·세로 위치 | 콤보가 자라는 법 |
| 감각 | 위젯 가로 크기, 콤보 유지 시간, idle 교체 간격 최소/최대 | 타격, 드래그 |
| 소리 | 볼륨, 음소거, 대기 소리 간격 최소/최대 | |
| 동작 | 돌아다니기와 이동 영역, 집어던지기, 항상 위에, 위치 잠금 | 이동, 던지기 |

**자주 안 만지는 값은 `상세 설정` 에 접어두었다.** 관련 값 옆에 붙여두었으니 이동 속도를 찾으러 다른 탭에 갈 일은 없다.
값이 서른 개 가까이 되면 뭘 얼마나 만졌는지 기억을 못 하는데 취소는 창을 통째로 되돌린다. 칸마다 **기본값으로** 를 두었다.

| 접힌 칸 | 만질 수 있는 것 |
|---|---|
| 콤보가 자라는 법 | 머리 위 틈, 한 계단 간격(기본 50 콤보), 계단당 커지는 폭, 최대 배율 |
| 타격 | 꾸겨지는 세기, 휘청이는 세기, 콤보당 증가폭, `beat` 유지 시간 |
| 드래그 | 뒤처지는 양, 늘어나는 한계, 복귀 스프링 세기 |
| 이동 | 걷는 속도 최소/최대, 쉬는 시간 최소/최대, 맞은 뒤·놓은 뒤 멈춤 |
| 던지기 | 던지는 세기, 최대 속도, 반발계수, 마찰, 멈추는 속도 |

설정은 `%AppData%\BeatIt\settings.json` 에 저장된다.

## 캐릭터 관리

설정 → **캐릭터** → **캐릭터 관리**. 폴더를 미리 만들어 오지 않아도 여기서 다 된다.

| 칸 | 할 수 있는 것 |
|---|---|
| 왼쪽 | 캐릭터를 새로 만들고, 베끼고, 이름을 바꾸고, 지운다. 밖에 만들어둔 폴더를 가져올 수도 있다 |
| 가운데 | 상태 칸 열넷. `idle`, `move`·`beat` 의 방향 다섯씩, `sounds` 셋. 오른쪽에 든 개수가 적혀서 어디가 비었는지 보인다 |
| 오른쪽 | 그 칸에 든 그림과 소리. 넣고, 갈아 끼우고, 뺀다. 그림은 썸네일로 보여준다 |

- 넣는 파일은 **참조가 아니라 복사**다. 원본을 옮기거나 지워도 캐릭터가 안 깨진다.
- 같은 이름이 이미 있으면 뒤에 번호를 붙인다. 덮어써서 있던 그림을 날리지 않는다.
- **기본 캐릭터(`claude`·`codex`·`gemini`)는 잠겨 있다.** 버전마다 앱이 다시 풀어놓는 것이라 고쳐봐야 되살아난다. `복사해서 만들기` 로 베낀 뒤 고치면 된다.
- `idle` 이 비어 있으면 캐릭터 목록에 안 잡힌다. 그 사실을 이름 옆에 적어준다.
- 넣고 뺀 것은 **창을 닫는 즉시 위젯에 반영된다.** 앱을 다시 켤 필요 없다.
- 소리는 첫 소리가 늦지 않게 미리 열어두느라 파일이 잠기는데, **이 창을 여는 동안은 위젯이 놓아준다.** 쓰고 있는 캐릭터의 소리도 그 자리에서 빼고 갈아 끼울 수 있다.

## 집어던지기

설정 → **동작** → 잡아서 집어던지기. 켜면 끌다 놓을 때 그 자리에 서지 않고 **놓은 순간의 속도로 날아간다.**

- 손 속도는 **최근 60ms** 를 지수 평균으로 다듬어 쓴다. 마지막 한 프레임만 보면 그 한 번이 유난히 짧거나 길게 잡혔을 때 엉뚱한 방향으로 날아간다.
- 놓기 전 **120ms 동안 손이 멈춰 있었으면 던질 뜻이 없는 것**으로 보고 그 자리에 내려놓는다. 이게 없으면 끌어다 조심히 놓아도 직전에 모아둔 속도로 날아가 버린다.
- 벽은 **이동 영역을 그대로 쓴다.** 돌아다니기가 꺼져 있어도 쓴다.
- 부딪히면 그쪽 `beat` 그림이 뜨고 타격 소리와 이펙트가 난다. **콤보는 안 센다.** 한 번 던져놓고 콤보를 쌓을 수 있으면 안 된다.
- 마찰로 느려지다 **멈추는 속도** 밑으로 떨어지면 공중이든 어디든 그 자리에 선다. **중력은 없다.** 있으면 언제나 영역 바닥에 가라앉아서 위젯을 원하는 자리에 둘 수가 없다.
- 날아가는 중에 누르면 **공중에서 낚아챈다.** 위치 잠금이 켜져 있으면 끌 수가 없어서 던지지도 못한다.

## 이동 영역

돌아다니기를 켜면 어디까지 갈지 정할 수 있다. 설정 → **동작** → 이동 영역.

| 고르는 값 | 범위 |
|---|---|
| 화면 전체 | 모니터를 다 합친 가상 화면 (기본) |
| 현재 모니터 | 위젯이 **지금 올라가 있는** 모니터. 다른 모니터로 끌고 가면 거기서 돈다 |
| 작업 영역 | 그 모니터에서 작업표시줄을 뺀 자리 |
| 직접 지정 | 화면이 어두워지고, 끌어서 그린 사각형 |

- **직접 지정**을 고르면 화면 전체를 덮는 오버레이가 뜬다. 끌어서 사각형을 그리고 `Enter` 로 확정, `Esc` 로 취소한다. 마음에 안 들면 다시 끌면 된다. 40x40 보다 작게 그리면 실수로 클릭한 걸로 본다.
- 영역 밖에 있어도 **끌어내지 않는다.** 다음 목적지가 영역 안이라 알아서 걸어 들어온다. 손으로 옮겨둔 자리를 앱이 멋대로 되돌리지 않게 하려는 것.
- 모니터를 빼거나 해상도를 바꿔서 저장해둔 영역이 화면 밖이 되면, **겹치는 만큼만 쓴다.** 하나도 안 겹치면 화면 전체로 돌아간다. 위젯이 안 보이는 데로 사라지지 않는다.
- 영역은 **위젯 창 전체**가 들어가는 범위다. 창은 늘어나고 흔들려도 안 잘리게 여백을 크게 잡아두기 때문에, 캐릭터는 그린 경계보다 조금 안쪽까지만 간다.

## 테마 관리

설정 → **테마** → **테마 관리**. 캐릭터 관리와 같은 3단이고, 폴더를 미리 만들어 오지 않아도 여기서 다 된다.

| 칸 | 들어가는 방식 |
|---|---|
| 타격 이펙트 | 이름 제한 없이 여러 장. 캐릭터의 `idle` 칸과 같다 |
| 콤보 숫자 0~9 | **자리 열 개가 정해져 있다.** 자리를 고르고 `이 자리에 넣기` 를 누르면 그 숫자 이름으로 베껴 들어간다 |
| 콤보 라벨 | 자리 하나(`label`). 비워두면 글자로 그린다 |
| 콤보 폰트 | `.ttf` / `.otf`. 여러 개를 넣어도 첫 장만 쓴다 |

- 빈 자리도 테두리를 둘러 보여준다. **열 자리가 다 차야** 숫자 그림으로 그려지기 때문에, 어디가 비어 글꼴로 떨어지는지 한눈에 보여야 한다. 칸 목록에는 `3/10` 처럼 몇 자리가 찼는지 적힌다.
- 같은 자리에 `3.png` 와 `3.gif` 가 함께 남으면 어느 쪽이 그려질지 알 수 없으므로, 채울 때 그 자리의 옛 확장자를 치운다.
- **기본 테마 `default` 는 잠겨 있다.** 캐릭터와 같은 이유다. `복사해서 만들기` 로 베낀 뒤 고치면 된다.

## 에셋 갈아끼우기

그림만 넣으면 기본값을 바꿀 수 있다. 전부 `%AppData%\BeatIt\` 아래에 있고, 설정 창의 **폴더 열기** 버튼이 바로 그 폴더를 연다.
캐릭터는 **캐릭터 관리** 창에서 앱을 안 나가고도 같은 일을 할 수 있다. 아래는 그 창이 실제로 만드는 모양이다.

### 캐릭터 — `characters\<이름>\`

```
내캐릭터/
  idle/              대기 중 랜덤하게 돌아가며 뜬다. 이것만 필수다
  move/              끌고 갈 때, 돌아다닐 때 뜬다
    default/         방향을 안 따질 때
    left/ right/     가는 쪽에 맞춰 뜬다
    up/ down/        (선택)
  beat/              맞을 때 뜬다
    default/         가운데를 때렸을 때
    left/ right/     그쪽을 때렸을 때
    up/ down/        (선택)
  sounds/
    idle/ move/ beat/  그 행동을 할 때 하나씩 무작위로 울린다
```

- 장수 제한 없다. PNG·JPG·**GIF**를 섞어 써도 된다. 같은 폴더에 여러 장이면 그중 하나가 랜덤으로 뜬다.
- **방향 폴더는 안 만들어도 된다.** `move/`·`beat/`에 이미지를 바로 넣으면 전부 `default`로 친다. 예전 캐릭터가 그대로 도는 이유다.
- 없는 방향은 `default`로, `default`도 없으면 `idle`로 대신한다. `move`·`beat` 폴더 자체가 없어도 `idle`로 때운다.
- 하위 폴더 없이 폴더에 이미지만 넣어도 된다. **단일 이미지 캐릭터가 이 경우다.**

**때린 자리 판정** — 캐릭터를 가로세로 각각 `[-1,1]`로 펴서 본다. 중심에서 반지름 0.25 안이면 `default`, 밖이면 45°씩 나눈 부채꼴 넷 중 하나다. 세로로 긴 캐릭터에서는 가운데 영역도 같이 세로로 늘어난다.

**가는 쪽 판정** — 6px 움직일 때마다 다시 정한다. 한 프레임 이동량은 1px도 안 돼서 그대로 쓰면 방향이 계속 뒤집힌다. 비스듬히 갈 때 위아래로 깜빡이지 않게, 세로로 넘어가려면 가로보다 1.4배 뚜렷해야 한다.

**소리** — 길이 제한 없다. `beat`는 맞을 때마다, `move`는 움직이기 시작할 때 한 번(방향이 꺾일 때는 다시 안 난다), `idle`은 설정한 긴 간격마다 운다. 같은 파일이 다시 걸리면 처음부터 다시 난다.
`wav`·`mp3`·`wma`·`m4a`·`aac`는 별도 설치 없이 나고, `ogg`·`flac`·`opus`는 그 코덱이 깔려 있어야 난다. **못 여는 파일은 알아서 목록에서 빠지므로** 섞여 있어도 무작위로 골랐을 때 조용해지지 않는다.

기본 제공: `claude`(idle 6 / move 4 방향별 / beat 10), `codex`(단일 이미지), `gemini`(단일 이미지).
`claude`는 일부러 두 방식을 섞어 두었다. `move`는 방향 폴더로 나눠 두었고 `beat`는 폴더에 이미지를 바로 넣었다.

### 테마 — `themes\<이름>\`

```
내테마/
  effects/   때릴 때 이 중 하나가 튄다. 비우면 이펙트가 안 뜬다
  combo/     콤보 숫자를 그리는 법
```

콤보는 있는 것부터 순서대로 쓴다.

1. `combo/0.png` ~ `9.png` 가 **전부** 있으면 그 그림으로 그린다. `label.png` 가 있으면 COMBO 자리에 쓴다.
2. 숫자 그림이 없고 `.ttf` / `.otf` 가 있으면 그 폰트로 그린다.
3. 둘 다 없으면 기본 글꼴로 그린다.

기본 테마 `default` 에는 이펙트 4장이 들어 있고 콤보는 기본 글꼴로 그린다.
폴더를 통째로 복사해 이름만 바꾸면 새 테마가 된다.

## 구조

```
src/BeatIt/
  Core/       타격·드래그·던지기, 콤보 수치와 표시 규칙, 캐릭터/테마/스프라이트, 방향 판정, 소리, 배회와 이동 영역, GIF 재생, 캐릭터·테마 칸 정의
  Models/     저장되는 설정 모델
  Services/   설정 파일 입출력, 캐릭터/테마 폴더 탐색과 편집, 내장 에셋 추출
  Views/      위젯 창, 설정 창, 캐릭터·테마 관리 창, 이동 영역 그리는 오버레이
  Controls/   콤보 표시, 설정 슬라이더 한 줄
  assets/     기본 제공 캐릭터·테마 원본과 exe 아이콘
tools/        아이콘·기본 이펙트 생성 스크립트
publish.ps1   배포용 exe 두 개 빌드
```

- **투명 창은 옮기는 게 비싸다.** 매 프레임 `Left`/`Top` 을 건드리면 화면 합성이 통째로 다시 도는데, 한 코어의 11% 였다(안 걸을 때 0.9%). 걷는 몫은 매 프레임 계산하되 창은 30fps 로만 옮겨 8.5% 로 줄였다. 아직 안 옮긴 몫을 태워 다음 목적지를 물어보기 때문에 경로와 속도는 그대로다.
  - 재는 구간이 40초는 돼야 한다. 돌아다니기는 걷다가 1.5~5.5초씩 쉬어서, 10초쯤 재면 쉬는 구간에 걸려 절반으로도 나온다.
  - 미뤄둔 시간은 **옮길 몫이 없을 때 같이 멈춰야 한다.** 쉬는 동안에도 쌓으면 빚이 남아서, 다시 걷기 시작할 때 쉰 만큼 매 프레임 옮긴다. 조여둔 게 대부분의 시간 동안 안 걸리게 된다.
- 같은 이유로 이동 영역 오버레이도 화면 전체를 덮는 투명 창이다. 덮개는 사각형 네 장으로 그리고 다시 그리는 주기는 33ms 로 조여두었다. 화면 전체짜리 지오메트리를 마우스마다 새로 만들던 때는 끌고 있는 동안 프로그램이 멈춘 것처럼 느껴졌다.
- 애니메이션은 Storyboard 대신 감쇠 스프링(`Core/Spring.cs`)으로 돌린다. 타격을 임펄스로 밀어넣기 때문에 연타하면 흔들림이 끊기지 않고 누적된다.
- GIF는 외부 패키지 없이 `GifBitmapDecoder` 로 프레임을 직접 합성한다(`Core/AnimatedGifPlayer.cs`). 부분 갱신 프레임과 disposal 규칙을 처리한다.
- 어떤 그림을 그릴지는 `ISpriteSource` 뒤에 있다. 창은 매 프레임 "지금 idle인지 move인지, 어느 쪽인지"만 넘기고, 고르는 규칙은 `CharacterSpriteSource` 안에 있다.
- 방향 폴백(`left` 없음 → `default` → `idle`)은 `DirectionalSprites`가 쥐고 있고, **폴백해도 같은 목록 인스턴스를 돌려준다.** 덕분에 창이 방향을 바꿔 물어봐도 후보가 그대로면 그림을 새로 뽑지 않아 걸을 때 산만해지지 않는다.
- 소리는 파일마다 `MediaPlayer`를 미리 열어두고 재생할 때 되감기만 한다(`Core/SoundBank.cs`). 매번 열면 첫 소리가 늦는다. 코덱이 없어 못 여는 파일은 `MediaFailed`가 올 때 목록에서 뺀다.
- **어느 모니터에 올라가 있는지는 WPF만으로 못 구한다.** `SystemParameters.WorkArea`는 주 모니터 것뿐이라, `MonitorFromPoint` + `GetMonitorInfo`를 직접 부른다(`Services/MonitorBounds.cs`). 한 번 호출로 그 모니터의 전체 영역과 작업 영역을 같이 준다. WinForms 참조를 켜면 `Screen` 으로 되지만 그것 때문에 배포 exe 가 크게 불어난다.
- 영역을 그리는 오버레이는 **가상 화면과 정확히 겹치는 창**이라 좌표 변환이 없다. 창 안 좌표에 창 위치만 더하면 그게 곧 `Window.Left/Top` 좌표다.
- 캐릭터 칸의 이름과 설명은 `Core/CharacterSlot.cs` 한 군데에 있다. 편집기 목록과 설명 문구가 갈라지지 않게 하려는 것. 테마는 `Core/ThemeSlot.cs` 가 같은 일을 한다.
- 콤보가 **얼마나 크고 무슨 색인지는 `Core/ComboStyle.cs` 가 혼자 안다.** 그리는 쪽(`ComboDisplay`)과 자리를 잡는 쪽(창)이 같은 답을 봐야 하기 때문이다. 창은 콤보가 커진 만큼 머리 위를 비워야 하는데, 그 높이를 따로 계산하면 언젠가 어긋나 숫자가 잘리거나 캐릭터를 덮는다.
- 콤보 자리는 **계단이 바뀔 때만** 다시 잡는다. 최대 배율에 맞춰 늘 크게 잡아두면 콤보를 안 쌓는 대부분의 시간 동안 화면 절반만 한 투명 창을 들고 있게 된다. 콤보가 안 떠 있으면 아예 안 비워서 평소 창 크기는 예전 그대로다.
- 폴더를 만들고 베끼고 이름을 바꾸고 지우는 일은 캐릭터와 테마가 완전히 같아서 `Services/FolderLibraryEditor.cs` 하나가 맡는다. 손대는 곳을 그 묶음의 뿌리 **바로 아래**로 묶어두었고, 그 밖을 가리키는 경로는 거절한다. `CharacterEditor` 는 상태별 칸을, `ThemeEditor` 는 이름이 정해진 콤보 자리를 다루는 몫만 남는다.
- 관리 창을 닫으면 경로가 그대로여도 캐릭터와 테마를 **통째로 다시 읽는다.** 평소의 미리보기는 경로가 같으면 안 읽어서, 방금 넣은 그림이 앱을 껐다 켜야 나왔다. 여는 동안에는 위젯이 소리를 놓아주어 쓰고 있는 캐릭터의 소리도 갈아 끼울 수 있다.
- 설정 한 줄(이름·슬라이더·지금 값)은 `Controls/SliderRow.xaml` 하나다. XAML 에 `Grid` 세 칸을 매번 펴 두면 값 하나 늘릴 때마다 열다섯 줄을 베끼게 된다.
- `AppSettings.Clone` 은 `MemberwiseClone` 으로 뜬다. 필드를 손으로 적어 옮기면 값을 늘릴 때 한 줄을 빠뜨리기 쉽고, 그러면 **그 값만 취소가 안 먹고 미리보기가 안 도는** 조용한 버그가 된다.
- 설정 창은 `ISettingsPreview` 로 위젯에 값을 비춰본다. 매번 복사본을 넘기므로 위젯이 무엇이 바뀌었는지 비교해 **바뀐 것만 다시 읽는다.** 슬라이더를 끄는 동안 이미지를 다시 읽지 않는다.
- 기본 에셋은 빌드할 때 `assets/characters` 와 `assets/themes` 를 각각 zip 으로 묶어 리소스로 넣는다(`PackCharacters` 타깃). 파일을 하나씩 리소스로 넣으면 리소스 이름에서 원래 폴더 구조를 되살릴 수 없다.

## 알아둘 점

- 기본 에셋은 **버전마다 한 번만** 풀린다. 그래서 기본 캐릭터를 지워도 되살아나지 않는다. 반대로 새 기본 에셋을 추가했으면 `BeatIt.csproj` 의 `<Version>` 을 올려야 기존 사용자에게도 풀린다.
- 푸는 건 **없는 파일만**이라 옮긴 파일은 옛 자리에 그대로 남는다. 1.1.0 이전부터 쓰던 사람은 `claude\move\` 에 방향 폴더가 생긴 뒤에도 평면 이미지 5장이 남아 있다. 동작엔 문제없고(그냥 `default` 후보가 된다) 지워도 된다.
- 기본 캐릭터 `clawd` 는 1.3.0 에서 **`claude` 로 이름을 고쳤다.** 쓰던 사람의 폴더와 그 안 파일 이름을 앱이 옮겨준다(`Services/BundledAssets.cs`). 옮기지 않으면 곧 풀릴 새 이름 그림과 같은 그림이 두 벌이 되어 랜덤으로 뽑을 때 같은 장이 두 배로 걸린다. 이름만 고치니 그 그림을 손봐뒀어도 그대로 남고, 설정에 적어둔 경로도 같이 따라간다.
- **설정 창에서 목록을 띄우는 동안 다른 창을 숨기면 안 된다.** WPF 콤보는 `SelectionChanged` 를 부를 때 아직 목록 팝업을 안 닫았다. 그 자리에서 주인 창을 숨기면 소유 팝업이 같이 숨었다가 되살아나 화면 구석에 박힌다. WPF 는 이미 닫은 걸로 알고 있어서 닫지도 옮기지도 못하고, 콤보가 쥔 마우스 캡처 때문에 앱 전체 클릭이 먹힌다. 이동 영역 오버레이를 `Dispatcher` 로 한 틱 미뤄 여는 이유다.
- `.ps1` 파일은 **UTF-8 BOM** 으로 저장해야 한다. Windows PowerShell 5.1 은 BOM 없는 파일을 cp949 로 읽어서, 한국어 주석이 뒤따르는 코드 줄을 먹어버린다.
- Win32 는 물리 픽셀로, WPF 는 DIP 로 말한다. 모니터 영역은 `CompositionTarget.TransformFromDevice` 로 바꿔서 쓴다. 배율이 다른 모니터를 섞어 쓰면 경계가 몇 px 어긋날 수 있다.
- 창 크기는 현재 이미지의 비율로 잡는다. 한 캐릭터 안에 비율이 다른 이미지를 섞으면 나머지는 그 상자 안에 `Uniform` 으로 맞춰 들어간다.
- 늘어나고 흔들려도, 콤보를 멀리 밀어놔도 잘리지 않게 창을 넉넉히 잡아두었다. 남는 여백은 클릭이 통과한다.
- 이펙트는 여러 개가 동시에 뜰 수 있어 각자 재생 상태를 가질 수 없다. `effects/` 에 GIF를 넣으면 첫 프레임만 쓴다.
- 콤보에 **숫자 그림을 쓰는 테마에서는 색이 안 입혀진다.** 그림을 물들이면 원래 색이 뭐였는지 알 수 없어진다. 계단마다 커지는 것과 마일스톤 연출은 그대로 된다.
- 던지기를 켜고 마찰을 0 으로 두면 **영영 튄다.** 영역은 못 벗어나니 위험하진 않지만 스스로 멈추지 않는다. 잡으면 멈춘다.
- 움직이는 그림은 **GIF만** 돈다. `.webp`는 Windows의 WebP 코덱이 깔려 있어야 읽히고, 읽혀도 첫 프레임만 나온다.
